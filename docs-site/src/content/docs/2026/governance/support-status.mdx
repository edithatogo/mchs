This page documents the canonical support status vocabulary and the current
status for every stream, surface, runtime, and language. The project uses
fail-closed semantics: no support status may be inferred from absence of
evidence. See the [validation ladder](#validation-ladder) below for how a
stream moves from discovery through to GA.

## Canonical statuses

| Status | Meaning |
| --- | --- |
| `unsupported` | The project does not support this stream, year, jurisdiction, or surface. |
| `blocked` | Support is desired but blocked by missing source, licence, parity, implementation, or release evidence. |
| `planned` | Work is planned but not implemented. |
| `deferred` | Work is intentionally paused behind explicit audience, owner, contract, or evidence gates. |
| `canary` | Experimental implementation exists for limited synthetic or internal fixtures. |
| `opt_in` | Users may explicitly enable the surface or stream; it is not default. |
| `preview` | Local or pre-release implementation exists, but publication or default support is not claimed. |
| `release_candidate` | Release evidence is complete enough for final validation before GA. |
| `ga` | Supported by default for the declared scope. |
| `no_new_development` | Roadmap entry is retained, but active implementation is paused unless reprioritised. |
| `historical` | Prior work or context retained for traceability, not an active product commitment. |

## Validation ladder

A pricing year or stream moves through these stages. Each stage requires
explicit evidence before promotion:

1. **Discovered** — Official sources are identified.
2. **Archived** — Sources are archived or explicitly gap-recorded.
3. **Extracted** — SAS logic, Excel formulae, workbook tables, price weights,
   and supporting parameters are extracted into structured bundles.
4. **Source-parity-checked** — Implementation logic is compared with SAS and
   Excel formulae where available.
5. **Fixture-parity-checked** — Outputs are checked against official SAS/Excel
   or trusted reference outputs.
6. **Cross-engine-checked** — Python, Rust, CLI, and released bindings agree on
   shared fixtures.
7. **Validated** — Evidence records are complete and linked from manifests/docs.

See the canonical source in [Conductor roadmap-governance.md](https://github.com/edithatogo/microcosting_healthservices/blob/master/conductor/roadmap-governance.md).

## Fail-closed rules

- Missing source evidence is `blocked`, not inferred support.
- Missing parity evidence is `blocked` or `canary`, not GA.
- Deferred language surfaces are `deferred` when they have an explicit future path, or `no_new_development` when retained only as roadmap context.
- Prior SQL/DuckDB references are `historical` unless reprioritised.
- Public docs must show the narrowest truthful status.
- No surface may claim GA status without completing all [promotion criteria](/2026/governance/polyglot-rust-core-roadmap/).
